Problem

Clinical and molecular test data arrives in inconsistent formats, while oncology classification depends on rules, thresholds, synonyms, and subtype logic that change over time.

What I built

I originally built this capability within a commercial oncology data platform in partnership with bioinformatics SMEs. Because the production system is proprietary, I rebuilt OncoKG as a live, non-proprietary demonstration using synthetic data.

Why it matters

The architecture separates domain knowledge from application code, making rules easier to extend, test, audit, and govern.

All patients and lab results here are synthetic. No proprietary code, data or rules from any production system are included. Thresholds follow cited published guidelines where noted, but OncoKG is a demonstration, not a validated clinical decision tool.

Pipeline

Accuracy by diagnostic class

Most specific class per patient (molecular subtype if present, else histology/receptor subtype). Sensitivity = found ÷ true cases; PPV = correct ÷ calls made. Misses are mostly abstentions ("indeterminate" or a correct but less specific parent class), not wrong calls.

Molecular modifiers

Non-exclusive annotations (HER2-low/ultralow/null, BRCA1/2, PIK3CA, TMPRSS2::ERG, PD-L1…). Recall is limited by missing tests, low purity and depth QC; no false positives were produced.

    Tissue-of-origin evidence weights

    okg:LineageEvidence. A lineage is assigned at score ≥ 3 with a margin ≥ 2 over the runner-up; prostate also requires male sex. Specimen site adds 1.5.

    Diagnostic rules

    Rule groups run in order. Within a group the first rule (by priority) whose criteria all hold assigns its class. Missing data never satisfies a criterion unless the rule says so.
